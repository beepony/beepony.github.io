    The History of Ruby

    Many people think Ruby is a young language, but it was actually released in 1994 by a developer named Matz. Matz is a geek obsessed with programming languages and a big fan of Perl. He created Ruby hoping it would be as flexible and powerful as Perl, but with richer syntax and more readable code.

    Ruby quickly gained a following. But before 2000, all Ruby documentation was in Japanese, so if you wanted to learn Ruby, you had to learn Japanese first. Dave Thomas, a pioneer of agile programming, fell in love with Ruby and decided to write documentation for it. He wrote an influential book called The Pickaxe , named for the picture on its cover. This book opened a window for the English-speaking world to learn about Ruby.

    More people in the English-speaking world started to know Ruby, but growth was very slow. Only when system administrators started writing maintenance and "glue" scripts in Ruby (previously written in Perl) did Ruby start to catch on. From 2000 to 2005, the US
    Ruby community had a few hundred members.

    In 2004-2005, a Chicago company called 37signals hired a young programmer to build a web application. They cared only about the client-side design and functionality and gave the young programmer enormous freedom in the implementation. At the time, the main web technologies were Perl CGI, PHP, JSP, ASP, and so on, each with its own pain points. So David, whom we now call DHH, blazed a new trail.

    He built the application in Ruby. Apart from the core libraries and a few helper libraries, he did almost everything himself. He and 37signals both worked on this application, which is now called Basecamp.

    After Basecamp was finished, DHH extracted a web framework from the application. Unlike the top-down frameworks of Java and .NET, Rails was extracted entirely from a real-world case. It follows the principle of convention over configuration, making common problems easier to solve.

    Rails was a huge success, and it drove enormous growth in the Ruby community. Today you can buy a dozen books about Ruby on Amazon, there are hundreds of Ruby conferences around the world, and thousands of people have become professional Ruby/Rails developers.

    If you want to learn Rails, learn Ruby first. Let's go…

    1. A Quick Overview and the Interpreter

    Ruby is an interpreted language, which means it doesn't run directly on the processor. It runs through a virtual machine. The advantage is that you write it once and it runs on all kinds of operating systems and hardware platforms.

    A Ruby program can't run on its own; you need to load the virtual machine first. There are two ways to run Ruby code in the VM: IRB and the command line.

    Running Ruby from the Command Line

    Writing Ruby code in a file is the most common and reliable approach. Files can be backed up, shared, added to source control, and so on.

    2. Variables

    Programming is about creating abstractions. To create abstractions, we need to give things names, and variables are how we name data.

    In some programming languages, a variable can hold only a specific type of data. Ruby doesn't require this; it has a very flexible type system, and any variable can hold any type of data.

    Creating and Assigning Variables

    In some programming languages, you have to declare a variable before assigning it. Ruby variables are created automatically when you assign them, with no declaration needed. Here's an example

    The statement a = 5 creates the variable a and stores 5 in it.

    Read from the Right

    In everyday reading, we read left to right, so it feels natural to read code that way too. But when assigning with =, Ruby actually evaluates the right side first. For example:

    10 + 5 is evaluated first, then the result is assigned to the variable b.

    Flexible Variable Assignment

    Ruby variables can hold any type of data and can even change the type they hold. For example:

    First c is assigned 20, then the string "hello" is assigned to c, and c's value becomes "hello."

    Variable Naming Rules

    The virtual machine has format requirements for most Ruby variable names. Generally, they

    • Start with a lowercase letter (an underscore also works, but it's uncommon)
    • Have no spaces
    • Can't contain special characters such as $, @, &, etc.

    Beyond that, Ruby programmers share some common naming conventions:

    • All words lowercase and joined by underscores
    • Named after what the variable holds, not its type
    • Not too short

    Good variable names look like count, students_in_class, or first_lesson.

    Don't write names like these:

    • studentsInClass - uses camelCase instead of underscores; it should be students_in_class
    • 1st_lesson - variables can't start with a number; it should be first_lesson
    • students_array - the format is fine, but the name describes the data type, so it's not idiomatic; it should be students
    • sts - too short; just use students

    3. Strings

    In real life, a string is a cord you can use to tie things up. Strings in programming have nothing to do with that.

    Strings store collections of numbers and letters. They can be a single letter "a," a word "hi," or a sentence like "hello world!"

    Writing Strings

    A Ruby string starts with a quote, contains zero or more letters, numbers, and symbols, and ends with a quote. The shortest string is the empty string "". It's not unusual for a string to hold a paragraph or even several pages of text.

    4. Symbols

    Symbols are harder to explain; they're somewhere between strings and numbers. Symbols are easy to recognize: they start with a colon followed by letters, like :flag or :best_friend.

    If You're New to Programming

    If you're new to programming, think of a symbol as a stripped-down string without many methods or string interpolation. Compare the methods a string supports with those of a symbol

    If You're an Experienced Programmer

    If you're an experienced programmer, think of a symbol as a "named integer." The actual value a symbol refers to doesn't matter; what matters is that any reference to it anywhere in the VM returns the same value. Symbols are defined in a global symbol table, and their values never change.

    8. Hashes

    A hash is also a collection of data, but unlike an array, its data has no order, and each item has a name. It's a lot like a fridge. When we look for something in the fridge, we don't really care which shelf it's on. Order doesn't matter. Instead, we sort things by name: 3 apples, 1 orange, 12 carrots. That's when we use a hash.

    9. Conditionals

    A conditional expression evaluates to ture or false. The most common conditional operators are ==, >, >=, <, <=.

    Some object methods also return true or false, so they work as conditional expressions too. For example, every object has a .nil? method, which returns true when the object is nil. Arrays have a method called .include?, which returns true when the array contains the element. By Ruby convention, methods that return true or false end with a ?.

    Understanding the Flow

    When minutes is 5, Ruby first checks whether it's less than 7. It is, so it prints The water is not boiling yet..

    When minutes is 7, 7 isn't less than 7, so it moves on. It equals 7, so it prints It's just barely boiling.

    When minutes is 8, Ruby checks whether 8 is less than 7. It isn't. It checks whether 8 equals 7. It doesn't. Moving on, it checks whether 8 equals 8. It does, so it prints It's boiling!.

    When minutes is 9, the same logic applies and the last statement runs: Hot! Hot! Hot!.

    Possible Forms of an if Statement

    An if statement can have...

    • Exactly one if statement, which runs only when its condition is true
    • Zero or more elsif statements, which run only when their condition is true
    • Zero or one else statement, which runs only when none of the if or elsif conditions are true.

    Only one branch of an if/elsif/else structure can run. If the if condition is true, Ruby skips the elsif branches entirely. Only one block runs at a time. That's it.

    Equality vs. Assignment

    The most common mistake when writing conditionals is mixing up = and ==.

    • = is assignment. It puts the value on the right into the name on the left. It's a statement, not a question
    • == is a question. It asks whether the thing on the left equals the thing on the right. It's a question, not a statement

    You can also combine conditionals with logical operators. The most common are logical AND and logical OR, written as && and ||.

    10. Nil & Nothingness

    What is nothingness? Does it only exist in outer space? When we think of nothing, isn't it just an abstraction of something? OK, that's getting too philosophical...

    In Ruby, nil means a value doesn't exist.

    If you have 3 eggs and eat all 3, you might think you have nothing. But in terms of eggs, you have 0. Zero is a number, not nothingness.

    If you have the string "hello" and delete the "h", "e", "l", and "o" characters, you might think you have nothing left. But you actually have "", an empty string. That isn't nothingness either.

    nil is Ruby's idea of nothingness. It shows up when you ask for something that doesn't exist. If we create an array with only 5 elements and insist on asking for the sixth, Ruby gives us nil. That doesn't mean the sixth slot is blank. Unlike a number, it simply doesn't exist: nil.

    Most errors you'll run into when writing Ruby involve nil. You think you're working with something and try to use it, but you can't operate on something that doesn't exist, so Ruby raises an error.

    11. Objects, Attributes, and Methods

    Ruby Is an Object-Oriented Language

    Ruby is an object-oriented language. Everything we work with in the virtual machine is an object. Every piece of data is an object. The information an object holds is called its attributes. The actions an object can perform are called its methods.

    For an example of an object, think of yourself as a person. Your attributes include height, weight, and eye color. Your methods include walking, running, washing dishes, and dreaming. Different objects have different attributes and methods. In the next section, we'll look at common Ruby objects.
